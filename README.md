# Educational Media Portal — Runbook

A zero-cost, touch-friendly portal that serves study material (PDFs, images,
videos) to the kiosk tablets over Wi-Fi. Administrators upload and publish
resources from a web dashboard; students browse them on the tablet without
anything being reinstalled or redeployed.

Implements the specification in [`../web-setup.md`](../web-setup.md).

**Start here** — every command below assumes you're in this folder:
`cd ~/Desktop/VED/tab-setup/tab-boot/web-portal`

Layout:

```
web-portal/
├── frontend/      React + TypeScript + Vite — kiosk portal and admin dashboard
├── worker/        Cloudflare Worker — auth, uploads, metadata, media delivery
├── migrations/    D1 schema
├── scripts/       Admin creation, dev helpers
└── wrangler.toml Worker + D1 + R2 + static assets configuration
```

**Pieces involved**

- **Frontend** (`frontend/`) — the student-facing portal (`/`, `/subject/:slug`,
  `/view/:id`) and the admin dashboard (`/admin`).
- **Worker** (`worker/`) — the API, the media endpoint and (in production) the
  host for the built frontend. One origin, no CORS, one deploy.
- **D1** (`media-db`) — metadata only: titles, subjects, file sizes, publication
  state. Never the file contents.
- **R2** (`media` bucket) — the private bucket that holds the actual files.

**Three rules that matter**

1. The R2 bucket stays **private**. Files are only served through
   `/media/:id`, which checks the publication state first.
2. Only **published** resources are visible to students. Drafts live in the
   admin dashboard and are served through the admin preview endpoint.
3. Object keys are **generated by the Worker**. Uploaded filenames are never
   used as a path, so a file called `../../etc/passwd` cannot escape its
   subject folder.

## Part A — One-time Cloudflare setup

Needs the free Cloudflare plan only. No custom domain, no paid services.

```bash
# 0. Install dependencies
cd ~/Desktop/VED/tab-setup/tab-boot/web-portal
npm install

# 1. Log in to Cloudflare (opens a browser)
npx wrangler login

# 2. Create the database, then copy the printed id into wrangler.toml
npx wrangler d1 create media-db

# 3. Create the private media bucket
npx wrangler r2 bucket create media

# 4. Apply the schema
npm run db:migrate:remote
```

Edit `wrangler.toml` and replace the placeholder:

```toml
database_id = "00000000-0000-0000-0000-000000000000"   # <- paste the real id
```

**Create the first administrator**

```bash
# Writes the account to the remote D1 database
node scripts/create-admin.mjs admin "choose-a-strong-password" --apply --remote
```

The password is stored as a PBKDF2-SHA256 hash (`100000` iterations — the
maximum the Workers runtime allows). The plaintext is never written anywhere.
Re-running the command with the same username resets the password.

> The iteration count is part of the stored hash, so an account created with
> an older build (which used more iterations) can no longer be verified and
> the sign-in returns a 500. Re-create the account with the command above.

## Part B — Run it locally

```bash
# Terminal 1 — the Worker (API + media) on http://localhost:8787
npm run dev:worker

# Terminal 2 — the frontend on http://localhost:5173
npm run dev:web
```

Or both at once with `npm run dev` (opens 5173 in your browser).

Local state lives in `web-portal/.wrangler/` — a local D1 database and a local
R2 bucket. Nothing touches the cloud until you deploy.

First run only:

```bash
npm run db:migrate:local                     # local schema
node scripts/create-admin.mjs admin "test1234" --apply
```

## Part C — Deploy

```bash
# Builds the frontend, then publishes the Worker + assets
npm run deploy
```

The Worker serves the built React app from its static assets binding, so the
portal and the API live on the same origin
(`https://edu-media-portal.scholastic.workers.dev`). The tablet only ever
talks to that one address.

Optional extra secrets:

```bash
npx wrangler secret put ADMIN_BOOTSTRAP_USER      # only used while the admins table is empty
npx wrangler secret put ADMIN_BOOTSTRAP_PASSWORD
```

## Part D — Using the dashboard

1. Open `https://<your-worker-url>/admin` and sign in.
2. **Upload resource** — set a title, pick the subject, choose the file, tick
   *Publish immediately* (or leave it off and publish later).
3. **Resources** — publish, unpublish, edit, preview or delete each item.
4. **Storage** — usage against the 10 GB free R2 allowance, with a warning once
   you pass 70%.

Upload behaviour:

| File size | How it is sent |
|---|---|
| ≤ 8 MB | One request (`PUT /api/admin/uploads/:id/file`) |
| > 8 MB | Multipart upload, 8 MB parts, up to 3 retries per part, progress bar |

If the browser is closed mid-upload, the half-finished upload is aborted and
deleted by the nightly cron (`17 3 * * *`), so it cannot pin storage.

## Part E — Pointing the kiosk at the portal

The tablet runs the DPC in lock-task mode. The portal is **not** opened in a
browser — the DPC hosts it in its own full-screen WebView, so there is no
address bar, no tab strip and no way to reach another site. The feature is
off until a URL is set:

```java
// KioskDPC -tab/KioskDPC/app/src/main/java/com/kioskdpc/controller/KioskConfig.java
public static final String PORTAL_URL = "https://edu-media-portal.scholastic.workers.dev/";
public static final String PORTAL_ALLOWED_HOSTS = "";   // empty = the host of PORTAL_URL only
```

`PortalActivity` loads that URL in a WebView, refuses any navigation to a
host that is not on the allow-list, and blocks pop-ups. The hub shows the
green **Learning Portal** button only when `PORTAL_URL` is set, so the kiosk
behaves exactly as before until the portal is switched on.

**PDFs.** A WebView cannot draw PDFs, so the portal detects the kiosk WebView
and switches to its own PDF.js renderer. Chrome keeps its native PDF viewer.
PDF.js is pinned to the 3.x series on purpose: the tablet's WebView is from
2021 (Chrome 94) and PDF.js 4+ needs a much newer browser.

Rebuild the DPC, reinstall it, relaunch. No re-provisioning needed.

The full procedure lives in `../SETUP.md` (Part H).

## API reference

Public (no authentication):

| Method | Endpoint | Purpose |
|---|---|---|
| `GET` | `/api/media?subject=Physics&q=&type=pdf` | List published resources |
| `GET` | `/api/media/:id` | Published resource metadata |
| `GET` | `/media/:id` | Deliver the file, with HTTP Range support |

Admin (session cookie required):

| Method | Endpoint | Purpose |
|---|---|---|
| `POST` | `/api/admin/login` | Sign in, sets the session cookie |
| `POST` | `/api/admin/logout` | Sign out |
| `GET` | `/api/admin/session` | Current administrator |
| `GET` | `/api/admin/media` | List every resource, published or not |
| `POST` | `/api/admin/uploads` | Start an upload, returns the session |
| `PUT` | `/api/admin/uploads/:id/file` | Send a small file in one request |
| `PUT` | `/api/admin/uploads/:id/parts/:n` | Send one part of a large file |
| `POST` | `/api/admin/uploads/:id/complete` | Finish a multipart upload |
| `DELETE` | `/api/admin/uploads/:id` | Abort an upload and clean up |
| `PATCH` | `/api/admin/media/:id` | Edit metadata or publication state |
| `DELETE` | `/api/admin/media/:id` | Delete the resource and the file |
| `GET` | `/api/admin/media/:id/preview` | Preview an unpublished resource |
| `GET` | `/api/admin/storage` | Storage usage against the free tier |

The white-and-green identity lives in `frontend/src/styles/tokens.css` as CSS
custom properties — no colour is hardcoded anywhere else.

| Token | Value | Used for |
|---|---|---|
| `--color-background` | `#FFFFFF` | Page background |
| `--color-primary` | `#166534` | Buttons, headings, brand |
| `--color-secondary` | `#16A34A` | Accents, meter fill |
| `--color-surface-green` | `#F0FDF4` | Cards, toolbars, footer |
| `--color-selected` | `#DCFCE7` | Hover and selected states |
| `--color-border` | `#E5E7EB` | Borders and dividers |
| `--color-text` | `#1F2937` | Body text |

Touch targets are at least 48 × 48 px, there are no hover-only interactions,
and the layout works in portrait and landscape.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `d1 create` says the database already exists | Skip it and use the existing `database_id` in `wrangler.toml`. |
| `wrangler dev` fails: "assets directory not found" | Run `npm run build` once, or `node scripts/ensure-dist.mjs`. |
| Admin sign-in says "Incorrect username or password" | The account does not exist. Run `scripts/create-admin.mjs <user> <pass> --apply`. |
| Admin sign-in returns a 500 | The stored hash was made with more than 100000 PBKDF2 iterations, which the Workers runtime refuses. Re-create the account with the same command. |
| Local sign-in fails with `no such table: admins` | The `database_id` in `wrangler.toml` changed, so wrangler started a fresh local database. Run `npm run db:migrate:local`, then re-create the local admin. |
| Sign-in is blocked with "Too many failed attempts" | 10 failed tries from the same IP within 15 minutes. Wait it out or delete the row: `wrangler d1 execute media-db --remote --command "DELETE FROM login_attempts"`. |
| Video plays but seeking jumps to the start | The browser sent no `Range` header. Check that `/media/:id` answers `206 Partial Content`. |
| Large upload fails at the first part | The part is smaller than the 5 MB R2 minimum. `PART_SIZE` in `worker/src/constants.ts` is 8 MB. |
| Upload stays "Uploading" after a browser crash | The nightly cron removes it. `DELETE /api/admin/uploads/:id` removes it immediately. |
| Resources do not appear on the subject page | The resource is a draft. Publish it in the dashboard. |
| Student sees "Resource unavailable" | The file is missing from R2. Re-upload it. |
| Storage panel shows more than 70% | R2's free tier allows 10 GB. Delete or archive old videos. |

## Reference — free tier allowances

| Service | Free allowance | What we use it for |
|---|---|---|
| Cloudflare Workers | 100 000 requests/day | API calls, file delivery |
| Cloudflare D1 | 5 GB storage, 5 million reads/day | Metadata |
| Cloudflare R2 | 10 GB-month storage, free egress | The media files |
| Cloudflare Pages / assets | Free static hosting | The built React app |

Storage is the binding constraint: the media library should stay under 10 GB
and the dashboard warns at 70% usage.
